Before trusting
the chart, check the math.

I wanted the model to explain its own numbers. So I tested the rules behind the charts, not just the charts themselves.

01 / DEFINE

Start with the customer

A new subscription is not always a new customer. I calculate the ARR bridge at account level to avoid mixing them up.

02 / SEPARATE

Keep billing separate

Annual prepayments and one-time credits change the invoice total. They don't change the contract-based ARR in the same way.

03 / TEST

Make the numbers add up

Every month reconciles: opening ARR, new customers, expansion, contraction and churn add up to the closing balance.

The decision / Finance × RevOps

Get the numbers right.
Then explain why.

My takeaway: define ARR from contracts, use invoices to investigate billing, and check the differences before telling a story about growth. AI can help write the summary, but it shouldn't guess the reason.
